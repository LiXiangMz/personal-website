# Alex Morgan — photography portfolio

A single-page portfolio for a landscape and commission photographer: an
introduction, a curated set of photographs, an about section, a pricing table
and a contact block with a plain `mailto:` link.

Built with Next.js (App Router) and Tailwind CSS on a shadcn/ui preset
template. The template is committed verbatim in `00d74f2`; the site itself is
the commit that follows it.

## Running it

```bash
pnpm install
pnpm dev        # http://localhost:3000
pnpm build      # production build
pnpm start      # serve the production build
pnpm lint
pnpm typecheck
pnpm format     # prettier --write over the ts/tsx sources
```

`pnpm typecheck` runs `next typegen` first, so it works on a fresh clone
without a prior build. `next-env.d.ts` is generated by that step and is
deliberately not committed.

## Where things live

| Path | What it holds |
| --- | --- |
| `lib/content.ts` | **All copy and photo references.** Name, email, biography, works, section headings, table headers, pricing tiers, contact details. |
| `assets/photos/` | The photographs, imported by `lib/content.ts` and optimised by `next/image`. |
| `components/sections/` | One file per section: `hero`, `work`, `about`, `pricing`, `contact`. Layout only. |
| `components/site-header.tsx` | The sticky hairline header and its section links. |
| `components/site-footer.tsx` | Name, role, email, year. |
| `app/globals.css` | Colour tokens, the type scale, and the `label-caps` utility. |
| `app/fonts.ts` | Self-hosted Cormorant Garamond and Inter. |
| `app/layout.tsx` | Metadata, fonts, theme provider, header/footer frame. |
| `LICENSE-fonts.md` | OFL 1.1 notice and licence text for the two bundled typefaces. |

The split is strict: every sentence a visitor can read comes from
`lib/content.ts`. The components and `app/layout.tsx` hold layout, classes and
markup, so a copy change never means opening a component. The one piece of
generated copy is `workSection.summary` — the "n photographs, years" line above
the grid counts `works` and takes the year span from the entries, so adding or
removing a photograph keeps it accurate.

## Replacing the placeholder photographs

Every image currently in `assets/photos/` is a stand-in. Replace the file and
keep the name, or change the import in `lib/content.ts` — either way nothing
else needs to move.

| File | Used for | Crop it is displayed at |
| --- | --- | --- |
| `hero.jpg` | Full-bleed opening frame | 3:2 landscape (4:5 on phones) |
| `portrait.jpg` | About section portrait | 3:4 vertical |
| `work-01.jpg` | Selected work, frame 1 | 8:5 landscape |
| `work-02.jpg` | Selected work, frame 2 | 3:4 vertical |
| `work-03.jpg` | Selected work, frame 3 | 4:5 vertical |
| `work-04.jpg` | Selected work, frame 4 | 16:9 landscape |
| `work-05.jpg` | Selected work, frame 5 | 16:11 landscape |
| `work-06.jpg` | Selected work, frame 6 | 16:11 landscape |
| `work-07.jpg` | Selected work, frame 7 | 3:4 vertical |
| `work-08.jpg` | Selected work, frame 8 | 4:5 vertical |

Alongside each file, three things in `lib/content.ts` describe it and should be
updated at the same time:

- `alt` — what the photograph shows, for screen readers. It currently starts
  with `"Placeholder:"`.
- `title`, `place`, `year` — the caption under the frame.
- `placeholder` — the note naming the file and its crop; this is also the React
  key for the list item.

`hero.caption` under the opening image and `hero.alt` carry the same
placeholder wording. The `works` list uses `cell` for where a frame sits in the
twelve-column grid and `frame` for its crop; change `cell` only if you want a
different column rhythm. `sizes` is derived from `cell`, so the browser is
asked for an image close to the frame's real width.

To add or remove a photograph, edit the `works` array: the grid, the count and
the year span all follow from it.

## Replacing the rest of the copy

`site` in `lib/content.ts` holds the name, wordmark, role line, tagline, email
address, location, the meta description and `url` — the site's own address,
used for the canonical link, the social-card URL and the Open Graph image URL.
`url` is currently the placeholder `https://alexmorgan.example`; point it at
the real domain before publishing.

The email address appears in five places on the page — hero, pricing, the large
contact link, the footer, and the contact channel list — all reading from
`site.email`, so one edit covers them all.

Section headings and table headers live next to the copy they belong to:
`workSection.heading`, `pricing.heading`, `pricing.columns`, `pricing.caption`
and `pricing.cta`. The hero's opening sentence is `hero.intro` and its link
label is `hero.workLink`.

Prices live in `pricing.tiers` (`fee` and `unit` are displayed as-is, so any
currency works) and the three lines under the table in `pricing.notes`.

## Fonts

Cormorant Garamond (300, roman and italic) and Inter (variable, 300–600) are
self-hosted from `app/fonts/` and loaded through `next/font/local`, so the page
makes no request to a font CDN. Both are under the SIL Open Font License 1.1;
`LICENSE-fonts.md` carries the copyright notices and the full licence text.

## Theme and component scaffold

The site is light-only. `components/theme-provider.tsx` forces the theme and
exposes no switch — the template's bare `d` keyboard toggle is gone, so a
stray keypress cannot repaint the site, and `forcedTheme` means a `theme=dark`
value left in `localStorage` by an earlier build cannot repaint it either
(without it, `next-themes` prefers the stored value over the default and the
page would come up with `color-scheme: dark`: dark native scrollbars and form
controls on a light page). There are no dark tokens in `app/globals.css` and no
`dark:` utilities in the components.

The two `@hugeicons/*` packages are kept unused for now: `components.json`
names `hugeicons` as the icon library, so adding a shadcn component later
needs no dependency change. `@base-ui/react` and `class-variance-authority`
were removed along with the unused template `button.tsx`; add them back if a
component you pull in needs them.
